# Interswitch Phoenix (QuickTeller) API — Python Integration

Sample Python scripts for the **Interswitch Uganda Phoenix (QuickTeller) API**. They perform the security operations Phoenix requires — RSA signing and decryption, ECDH key exchange, and per-session AES encryption — so you can register a client and call the payment endpoints.

> **This is not a running service.** Unlike a middleware, these are standalone scripts you run from the command line (`python client_registration.py`, etc.). Copy the `utils/` helpers you need into your own Python application.

```
Your terminal  ──►  python <script>.py  ──►  Interswitch Phoenix API
                          │
                RSA / ECDH / AES handled in utils/
```

## What this provides

| File | Purpose |
| --- | --- |
| `generate_keys.py` | Generates the RSA-2048 key pair used for signing and decryption. |
| `client_registration.py` | Runs `clientRegistration` + `completeClientRegistration`; prints the **new `client_secret`**. |
| `key_exchange.py` | Runs `doKeyExchange` and derives the per-session AES key. |
| `customer_validation.py` | Validates a customer/account before payment. |
| `payment_notification.py` | Sends a payment notification (`xpayment`). |
| `status_check.py` | Checks the status of a previous transaction. |
| `balance_check.py` | Fetches the wallet/account balance. |
| `fetch_billers.py` | Lists biller categories, billers in a category, and biller payment items. |
| `utils/` | `AuthUtils` (InterswitchAuth headers), `CryptoUtils` (RSA/ECDH/AES), `HttpUtil`, `UtilMethods`, `Constants`. |
| `dto/` | Request/response objects and `PhoenixResponseCodes`. |

## Prerequisites

- **Python 3.14**
- A valid set of Interswitch-issued credentials:
  - `client_id` and `client_secret`
  - `terminal_id`, `serial_id`, and terminal password

> The default configuration points to the Interswitch **dev/sandbox** environment.

## Setup

1. Create and activate a virtual environment:

   ```bat
   py -3.14 -m venv .venv
   .venv\Scripts\activate
   pip install -r requirements.txt
   ```

2. Generate an RSA key pair and copy the output into `utils/Constants.py`:

   ```bat
   python generate_keys.py
   ```

   Paste the printed private key into `Constants.PRIKEY` and the public key into `Constants.PUBKEY`.

3. Fill in your credentials in `utils/Constants.py` (see below).

## Configuration

All runtime settings live in `utils/Constants.py`.

| Property | Description | How it is obtained |
| --- | --- | --- |
| `CLIENT_ID` | API client identifier | Issued by Interswitch |
| `CLIENT_SECRET` | API client secret | Issued by Interswitch; updated after registration |
| `TERMINAL_ID` | Terminal / merchant ID | Issued by Interswitch |
| `MY_SERIAL_ID` | Device serial ID, or a value used consistently across calls | Agreed with Interswitch or self-assigned |
| `ACCOUNT_PWD` | Terminal password (plain text; hashed internally before sending) | Set during registration |
| `PHONE_NUMBER` | Registered phone number | Issued with the terminal |
| `APP_VERSION` | Application version string | Your own versioning |
| `PRIKEY` | PEM RSA private key, used for signing and decryption | Generated by `generate_keys.py`; keep secret |
| `PUBKEY` | PEM RSA public key matching `PRIKEY` | Generated by `generate_keys.py` |
| `ROOT_LINK` | Phoenix API base URL | Interswitch environment URL (dev URL is the default) |
| `BILLERS_BASE_URL` | Biller management base URL | Interswitch environment URL |

> The `PRIKEY`/`PUBKEY` shipped in the repository are **sample keys**. Replace them with your own before doing anything real.

## Partner integration flow

Follow these steps the first time you connect to Phoenix:

1. **Generate an RSA key pair**

   ```bat
   python generate_keys.py
   ```

   Save the output into `Constants.PRIKEY` and `Constants.PUBKEY`.

2. **Register the client**

   ```bat
   python client_registration.py
   ```

   This performs both `clientRegistration` and `completeClientRegistration`. If successful, it prints a **new `client_secret`**.

3. **Update `Constants.CLIENT_SECRET`** with the value printed in step 2.

4. **Start transacting** using the payment scripts below. Each script runs `keyExchange` internally before its upstream request.

5. **(Optional) Test the auth flow on its own**

   ```bat
   python key_exchange.py
   ```

## Script reference

| Script | Phoenix endpoint | Method | Purpose |
| --- | --- | --- | --- |
| `generate_keys.py` | — | — | Generates the RSA key pair. |
| `client_registration.py` | `client/clientRegistration`, `client/completeClientRegistration` | POST | Registers and completes the client. |
| `key_exchange.py` | `client/doKeyExchange` | POST | Performs key exchange and derives the session key. |
| `customer_validation.py` | `sente/customerValidation` | POST | Validates a customer/account. |
| `payment_notification.py` | `sente/xpayment` | POST | Sends a payment. |
| `status_check.py` | `sente/status` | GET | Checks transaction status. |
| `balance_check.py` | `sente/accountBalance` | GET | Fetches the account balance. |
| `fetch_billers.py` | `Billers/categories-by-client/...`, `Billers/biller-by-category/...`, `Billers/items/biller-id/...` | GET | Lists biller categories, billers, and payment items. |

## Sample usage

Each script is run directly from the repository root and prints the remote request, the raw response, and the unmarshalled response.

```bat
python customer_validation.py
python payment_notification.py
python status_check.py
python balance_check.py
python fetch_billers.py
```

Request fields (amount, `customerId`, `paymentCode`, `requestReference`, etc.) are set inside each script. Update them to match the transaction you are testing.

## Response codes

Common Phoenix response codes, as defined in `dto/PhoenixResponseCodes.py`:

| Code | Meaning |
| --- | --- |
| `90000` | Transaction approved |
| `90001` | Transaction sent |
| `90006` | Error response from host |
| `90009` | Request in progress — query status later |
| `90020` | Transaction declined by biller |
| `90025` | Non-existent transaction |
| `90026` | Duplicate request reference |
| `90030` | Format error |
| `90051` | Insufficient funds |
| `90052` | Account / customer not found |
| `90054` | Expired PIN / OTP / token |
| `90055` | Wrong PIN or OTP |
| `90061` | Exceeds withdrawal limit |
| `90063` | Authorization error (often a signature issue) |
| `90091` | Remote system temporarily unavailable |
| `90092` | Routing error |
| `90096` | An error occurred |
| `70010` | Biller not found |
| `70038` | Data not found |

The full list is in the **Phoenix API Integration Specification** provided by the Interswitch technical team.

## Security notes

- `Constants.PRIKEY` is the root of trust. Store it securely, and never commit real credentials or keys to version control.
- The `PRIKEY`/`PUBKEY` checked into this repository are sample values for the sandbox. Replace them with your own key pair.
- `client_registration.py` prints the private key to the console. Do not keep or share that output.
- `utils/HttpUtil.py` disables TLS certificate verification (`verify=False`). Enable verification before any production use.
- After a successful registration, the returned `client_secret` replaces the initial value in all subsequent requests.
- Rotate keys and secrets periodically according to your security policy.

## Troubleshooting

| Problem | Likely cause | What to check |
| --- | --- | --- |
| `90063` authorization error | Invalid signature or wrong RSA keys | Ensure `PRIKEY` and `PUBKEY` are a matching pair copied correctly from `generate_keys.py`. |
| `keyExchange` fails | Wrong `client_secret`, `terminal_id`, `password`, or `serial_id` | Verify the credentials issued by Interswitch and check the printed response. |
| Duplicate reference (`90026`) | `requestReference` reused | Each script generates a fresh UUID — make sure you are not reusing one. |
| Installation fails building `cffi` | Wrong Python version | Use **Python 3.14**. The pinned `cffi==2.1.1` / `cryptography==50.0.1` provide Python 3.14 wheels. |
